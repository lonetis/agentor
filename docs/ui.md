# UI System

## Split Pane Layout

VS Code-style editor groups with recursive splits. Tabs can be dragged to any edge (left/right/top/bottom) to create horizontal or vertical splits, or to the center to merge into an existing group.

**Data model** (`useSplitPanes` composable, singleton module state):
- `rootNode: PaneNode | null` — recursive tree where each node is either a **leaf** (has `tabs[]`, `activeTabId`, `sizeFraction`) or a **container** (has `direction: 'horizontal'|'vertical'`, `children: PaneNode[]`, `sizeFraction`)
- `focusedNodeId` — which leaf receives new tabs from sidebar actions
- Type guards: `isLeaf(node)` / `isContainer(node)` — exported from composable
- Tree operations: splitting a leaf wraps it in a container; closing all tabs in a leaf collapses single-child containers recursively; same-direction splits insert as siblings (avoids unnecessary nesting)
- Public API: `rootNode`, `focusedNodeId`, `tabs`, `activeTabId`, `openTab`, `closeTab`, `closeTabsForContainer`, `focusGroup`, `moveTab`, `splitWithTab`, `resizeNodes`, `activateTab`

**Layout** (`SplitPaneLayout.vue` + `PaneSplitNode.vue`):
- `SplitPaneLayout` is a thin wrapper that renders a single `PaneSplitNode` rooted at `rootNode`
- `PaneSplitNode` is a recursive component: leaf nodes render `PaneGroupTabBar` + `PaneContent` + `PaneDropOverlay`; container nodes render `flex-row` (horizontal) or `flex-col` (vertical) with recursive children + `PaneSeparator` between them. A leaf takes focus on `pointerdown` (capture phase, so it still works when the terminal's touch handlers call `preventDefault`); the focused group's top border uses the theme accent (`--pane-tab-active-accent`). The container's size is measured once per separator drag (on `resizeStart`), not on every move. An `atLeadingEdge` prop marks the first-child chain, so only the top-left tab bar reserves room for the collapsed sidebar's expand button (see **Mobile & Touch Layout**)
- `PaneSeparator` accepts a `direction` prop — horizontal mode uses `cursor: col-resize`, vertical mode uses `cursor: row-resize`. It draws a 1px hairline (`--pane-tab-border`) that turns into the accent colour on hover / focus / drag, resizes with Pointer Events + pointer capture (mouse, touch, pen; `touch-action: none`, ±12px hit area on coarse pointers), emits `resizeStart` once and at most one `resize` per animation frame (the remainder is flushed on release). It is a focusable `role="separator"` (`aria-label="Resize panes"`, `aria-valuenow` = position in %) — ArrowLeft/Right (vertical separator) or ArrowUp/Down (horizontal) move it by 16px
- `PaneContent` mounts a tab on its first activation and then keeps it alive inside a `PaneTabHost` (`v-show`), so switching tabs is instant and sockets / iframes survive. `PaneTabHost` provides `PANE_ACTIVE_KEY`, which pauses the polling of hidden tabs (see **Polling**)
- `PaneDropOverlay` uses 5-zone nearest-edge detection (left/right/top/bottom at 25% threshold, center otherwise)

**Pane tab bar** (`PaneGroupTabBar.vue`): `role="tablist"` (`aria-label="Open panes"`); each `.tab-item` is a `role="tab"` with `aria-selected`, a roving `tabindex`, the full label as `title` and `aria-label`, and a truncated label (140px, 180px from 640px up). Keyboard: Enter / Space activate, ArrowLeft / ArrowRight / Home / End activate and focus a neighbour, Delete closes. The close button (`.pane-tab-close`, the tab's only `<button>`, `tabindex="-1"`) is named `Close <label>` with the tooltip "Close tab"; fine pointers fade it in on hover / focus, coarse pointers show a 28px close button on the active tab only and none on inactive tabs (so tapping an inactive tab always activates it). Middle-click closes a tab. The bar handles focus on `pointerdown`.

**Drag-and-drop** (`useDragTab` composable):
- HTML5 DnD API (`draggable`, `dragstart`, `dragover`, `drop`, `dragend`)
- `body.tab-dragging` class disables pointer events on iframes/xterm during drag
- `body.split-dragging` (horizontal) and `body.split-dragging-v` (vertical) during separator resize (and `split-dragging` during a sidebar drag)
- Drop zones: edge 25% → split in that direction, center → merge into leaf

**Terminal resize**: `ResizeObserver` on the terminal container element handles all resize scenarios (window resize, sidebar drag, pane separator drag) — no manual callback propagation needed.

## Tmux Tab Integration

Web-native tab bar inside the terminal pane — each tab represents a tmux window in the container's tmux session. Replaces manual tmux keyboard shortcuts with clickable tabs.

**Architecture** (`TerminalPane.vue` + `useTmuxTabs` + `TmuxTabBar`):
- `useTmuxTabs(containerId)` manages the tmux window list: fetches via API, polls every 3s for external changes (e.g. agent creating windows), provides create/close/activate/rename
- `TerminalPane` maintains a `Map<windowIndex, useTerminal()>` — one terminal per tmux window, all with live WebSocket connections
- `v-show` toggles visibility (not `v-if`) so hidden terminals keep their DOM, scrollback buffer, and WebSocket stream
- `TmuxTabBar` renders the inner tab bar (30px, dark theme, visually subordinate to the outer pane tab bar)
- Active window persisted per container in a module-level `Map` — survives outer tab close/reopen
- The main "shell" window cannot be closed or renamed — close button hidden, rename disabled
- New tab name input next to "+" button — type a name before creating, or leave empty for auto-generated `shell-{4char}`
- Click an already-active tab to inline-rename it (input replaces label, Enter to confirm, Escape to cancel)
- 10k scrollback per terminal, Alt+scroll for fast scrolling
- The bar's right edge holds pane actions (`#actions` slot) — currently the **touch keys** toggle (`aria-label` "Show/Hide touch keys")

## Terminal Input, Selection & Touch

`useTerminal` (one instance per tmux window) owns the xterm.js terminal and its WebSocket; `TerminalPane` wires the active window's instance to the toolbar, composer, text view and overlays. xterm.js and its addons are imported lazily (`loadTerminalClasses()`) when the first terminal pane mounts, so pages without a terminal never download them.

**Mouse protocol (selection fix).** xterm.js clears its selection on every "user input" event and treats mouse reports as input; with tmux `mouse on` (and any app asking tmux for any-motion tracking, e.g. crossterm TUIs) every mouse move was reported, so a selection vanished as soon as the pointer moved. xterm.js also disables local selection and touch scrolling while mouse reporting is on. The terminal therefore **never lets xterm.js enable mouse reporting**: parser hooks on `CSI ? Pm h/l` (plus RIS / DECSTR) record the requested protocol / encoding in a `MouseModeState` (`utils/terminal-mouse.ts`) and swallow those modes (other modes in a combined sequence are replayed). Clicks and drags are always local text selection (clicks were never forwarded to tmux); only the **wheel** is reported, encoded by `encodeWheelReport()` (SGR, SGR-pixels, urxvt, UTF-8, default) from a capture-phase `wheel` listener that also keeps xterm.js from turning the wheel into arrow keys. Ctrl+wheel stays browser zoom. Without application mouse tracking, xterm.js scrolls its own scrollback as usual.

**Clipboard.** macOS: Cmd+C / Cmd+V (browser copy/paste events). Elsewhere: Ctrl+Shift+C or Ctrl+Insert copy, Ctrl+C copies *while text is selected* (then clears the selection, so the next Ctrl+C interrupts), Ctrl+Shift+V / Shift+Insert paste through the browser's native paste event (bracketed paste when the app enabled it). `utils/clipboard.ts` falls back to `execCommand('copy')` in insecure contexts (plain http on a LAN IP) where `navigator.clipboard` does not exist. A right-click context menu (`UContextMenu`, disabled on touch) offers Copy, Paste, Select all, Open text view, Compose text, font size and the touch keys toggle. Links in the output are clickable (`@xterm/addon-web-links`).

**Touch** (`utils/terminal-touch.ts`, capture-phase listeners on `.terminal-surface`, which has `touch-action: none`):
- one-finger swipe → scroll with momentum; becomes wheel reports to tmux (copy-mode scrollback, ~1 report per 4 rows) or local scrollback without app mouse tracking
- long-press (450 ms) → selects the word under the finger (URLs/paths stay whole), drag to extend; then a floating **Copy / Select all / More… / ×** bar (`data-testid="terminal-selection-actions"`)
- two-finger pinch → font size (persisted)
- tap → left to the browser (focuses the terminal → soft keyboard; activates links)
- emulated mouse events during and for 800 ms after a swipe / long-press / pinch (e.g. Chrome's long-press `mousedown`) are swallowed, so they can neither clear the new selection nor pop up the keyboard

**Touch key toolbar** (`TerminalToolbar.vue`, `data-testid="terminal-toolbar"`, shown automatically on coarse-pointer devices, toggled from the tmux bar on any device): keyboard show/hide, Esc, Tab, latching **Ctrl** / **Alt** (applied to the next key, incl. the next character typed on the soft keyboard), arrows (hold to repeat), ⇧↵ (CSI-u Shift+Enter → newline in agents), ^C, Home/End/PgUp/PgDn, common symbols, font size −/+; fixed actions **Compose text**, **Paste**, **Select text**. Buttons prevent `mousedown` so tapping a key never closes the soft keyboard. Cursor keys respect DECCKM (`utils/terminal-keys.ts`).

**Composer** (`TerminalComposer.vue`, `data-testid="terminal-composer"`): a native textarea (16 px, so iOS does not zoom) where autocorrect, swipe typing, dictation and long-press paste work. **Send** pastes the text and presses Enter after 50 ms (TUIs treat an Enter inside a paste as part of it); **Insert** only pastes. Ctrl/Cmd+Enter sends. It also opens as the fallback when the async clipboard is unavailable or denied.

**Text view** (`TerminalTextView.vue`, `data-testid="terminal-text-view"`): the window's text incl. 3000 lines of tmux scrollback (`GET /api/containers/:id/panes/:windowIndex/capture?history=3000`, joined lines) as a natively selectable `<pre>` — OS selection handles, magnifier and copy menu on touch, Ctrl+F on desktop — plus Copy (selection or everything) and Reload. Falls back to the visible screen when the capture fails.

**Connection.** A dropped socket shows a "Disconnected — reconnecting…" pill (`data-testid="terminal-disconnected"`) with **Reconnect now** and reconnects automatically with backoff (0.5 s → 15 s) while the page is visible, on `online`, and when the page becomes visible again (also after > 30 s in the background, since mobile browsers silently kill background sockets). tmux redraws the screen on re-attach.

**Soft keyboard / viewport.** `plugins/viewport.client.ts` mirrors `visualViewport` into `--app-height` / `--app-offset-top`; the dashboard root uses `.app-shell` (fixed, sized to the visual viewport, safe-area padded), so the on-screen keyboard shrinks the layout (→ ResizeObserver → refit → tmux resize) instead of covering the terminal. Ignored while pinch-zoomed. xterm's hidden textarea and every terminal input use 16 px (no iOS focus zoom).

**Preferences** (`useTerminalPrefs`, persisted in `useUiState` → `terminal`): `fontSize` (null = device default: 12 px on phones, 14 px otherwise; 8–28) and `toolbar` (`auto` | `show` | `hide`). Device facts come from `useDevice()` (`isTouch` = `(pointer: coarse)`, `isStandalone`, `isMac`).

## Sidebar Worker Tabs & Mapping Groups

**Worker tabs** (`AppSidebar.vue`): the active workers are split across two mutually-exclusive tabs, mirroring how archived workers get their own tab.
- **Workers** lists every container whose `status !== 'stopped'` (running / creating / error / removing); **Stopped** lists `status === 'stopped'` containers. The Stopped tab sits between Workers and Archived. Both render the same `ContainerCard` (which already adapts to the stopped state — Restart instead of Stop, view/workspace buttons hidden), driven by a single `currentWorkerList` computed that selects the source list from `activeTab`. Tab badges count each list independently. Stopping a running worker moves it Workers → Stopped; restarting moves it back. The filtered lists are `activeContainers` / `stoppedContainers` computeds over the full `containers` prop — the mapping panels still receive the **full** list (for label resolution + the running-only worker dropdown).
- **Landmarks & tab bar**: the sidebar is `<aside aria-label="Sidebar">`, its section tabs a `<nav aria-label="Sidebar sections">` with `aria-current="true"` on the active tab. The **More** button (`aria-label="More tabs"`, `aria-haspopup`, `aria-expanded`) opens the overflow dropdown, which closes on an outside `pointerdown` and on Escape (handled in the capture phase with `preventDefault`, so the page-level Escape does not also close the phone overlay) and returns focus to the More button. The footer holds the account button, the PWA install button (`PwaInstallButton`, see **Progressive Web App**) and Sign out.

**Lifecycle actions** (`index.vue` → `runAction(id, label, fn)`): stop, restart, rebuild, remove, archive, save settings (`Save settings` / `Save & rebuild`), unarchive, delete archived, create and the refresh after an import all run through one helper. A reactive `busyIds` set ignores repeated clicks while an action for that worker is in flight; `AppSidebar` (`busyIds` prop) passes `:busy` to each `ContainerCard`, which then shows a spinning loader (`role="img"`, `aria-label="Working"`) next to its status badge (no buttons are disabled). A failure shows an error toast (`<Action> failed` + the server message via `fetchErrorMessage`) and a `console.warn` instead of failing silently. The native `confirm()` dialogs are unchanged — rebuild / remove / archive / delete check `busyIds` before asking.

**Worker card** (`ContainerCard.vue`): the header never scrolls — the display name (`<h3>`, opens Worker Settings on click) truncates with an ellipsis and the full name as `title`, while the status badge group stays visible on the right. The `creating` / `removing` badges carry a spinning loader icon. Every icon button's `aria-label` equals its tooltip text (Export uses one shared `exportLabel` for both), the group dividers are `aria-hidden`. The Worker Settings and Upload modals are mounted per card only on first open and then stay mounted (instead of one modal pair per card on every list refresh).

**Mapping groups** (`PortMappingsPanel.vue`, `DomainMappingsPanel.vue`): both panels group their mappings by owning worker. A `groupedMappings` computed buckets `mappings` by `m.workerId`, resolves each group's label via `workerLabelById` (live containers + archived workers, fallback `shortName`), and sorts groups by label. Each group renders a collapsible header (chevron + label + count badge) over its indented rows; a component-local `collapsedGroups` `Set<string>` of worker ids toggled by `toggleGroup(workerId)` drives `v-if` on the rows (so collapsing detaches them from the DOM). Groups default to expanded; collapse state is not persisted (resets on reload). Because the worker label now lives in the group header, the individual rows drop the per-row worker label and show only the internal port target (`:<port>`). Group headers expose `aria-expanded`; remove buttons are named `Remove mapping` (larger hit area on coarse pointers); form errors are `role="alert"`.

**Mapping forms**: both panels keep native `<select>` / `<input>` elements with visible borders and a focus ring and name them (`Mapping type`, `Worker`, `External port`, `Internal port`; `Subdomain (optional)`, `Path (optional)`, `Username`, `Password`). Port inputs bring up the numeric keyboard (`inputmode="numeric"`, `pattern`, `enterkeyhint`); text inputs turn off autocapitalize / autocorrect / spellcheck, and the basic-auth fields use `autocomplete="off"` / `new-password` so the browser does not fill in the dashboard login. Protocol and base-domain toggles expose `aria-pressed`; the basic-auth lock icon is `role="img"` "Basic auth enabled". **CA cert** downloads `agentor-ca.crt` in place through an `<a download>` (no popup — also works in an installed app).

## Worker Settings Modal

A worker's editable configuration lives in a single **Worker Settings modal** (`ContainerDetailModal.vue`) — there is no read-only detail view. Worker-related settings are split into two tiers; environment-specific settings (CPU/memory, network, Docker, capabilities, instructions, setup script, env vars, exposed APIs) are **not** shown here — they belong to the Environments modal.

- **Applies immediately (no rebuild)** — `displayName`. Saving applies it to the running worker immediately (the `PATCH` updates the stored label + in-memory state; no recreation). Tagged with a green `no rebuild needed` badge.
- **Rebuild-requiring edits** — `environmentId`, `repos`, `mounts`, `initScript`. Baked into the container at create time (the `WORKER`/`ENVIRONMENT` env JSON and Docker `Binds`), so saving only updates the stored desired config and flags the worker `pendingRebuild: true`. Each is tagged with an amber `requires rebuild` badge. A rebuild re-resolves from the stored config and clears the flag.

The modal computes which fields changed: a pure display-name change shows just **Save**; any rebuild-requiring change additionally shows **Save & Rebuild** (persist + rebuild now) plus a "Changes require a rebuild" hint. While `pendingRebuild` is set, the header shows a `Rebuild pending` badge and a banner with a **Rebuild now** button.

The flow front-to-back:

- **Create Worker modal**: the first field is labeled "Display name" (free-form, no keystroke sanitization). Its placeholder is a friendly suggestion fetched from `GET /api/containers/generate-name` (`{ displayName }`). On submit the client sends only `{ displayName }` (the typed value, or the suggestion when left blank) — never an `id`; the orchestrator mints the worker UUID.
- **ContainerCard**: shows `displayName || shortName(id)`. A "Settings" pencil button (`i-lucide-pencil`, in a `<UTooltip text="Settings">`) in the action row — and a click on the card title — opens the settings modal. When the worker has unapplied rebuild edits the card shows an amber `rebuild pending` badge next to its status. The card forwards an `update(id, patch, rebuild)` event (PATCH + optional rebuild) and a `rebuild(id)` event to `index.vue`'s `handleUpdate`, which relabels open tmux tabs when the display name changed and runs a rebuild when requested. The card also emits `export(id)` (→ `index.vue` `handleExportWorker` anchor download) and shows a per-worker live-metrics row (see **Resource Metrics & Worker Export/Import UI** below).
  - **Action row layout**: all buttons are left-aligned in logical groups separated by `w-px` vertical dividers — views (terminal/editor/desktop/apps) | workspace (upload/download/**export**) | lifecycle (settings/restart-or-stop/rebuild) | destructive (archive/remove). Views + workspace show only when running; lifecycle + destructive always. The row (`.card-actions`) is a single no-wrap flex strip with `overflow-x: auto` + hidden scrollbar; a vertical wheel over it scrolls horizontally (`onActionsWheel`), so it stays usable when the sidebar is narrow. On coarse pointers (touch screens) the row wraps onto several lines instead (`pointer-coarse:flex-wrap`) and every button gets ≈36px padding. The Rebuild button is neutral (not colored).
- **ContainerDetailModal**: read-only **Worker** identity section (Worker ID = the worker UUID `container.id` in monospace, Container ID = the Docker `container.containerId` first 12 chars, Image = `container.imageName`, Image ID, Created) + an editable **Settings** section (Display name `UInput`, Environment `USelect`, Repositories via `RepoInput`, Volume Mounts via `MountInput`, Init Script via `useInitScriptSync` preset + textarea) + read-only **Info** sections (Port Mappings, Domain Mappings, App Instances) shown only when present. The form re-initialises from the worker each time the modal opens, and the info sections reload on every open (superseded responses are dropped). Because the modal is mounted lazily, it fills an empty environment with the default once the environment list arrives and re-matches an untouched init script to its preset, so an unchanged form never looks dirty. `useContainers().updateContainerSettings(id, patch)` issues the `PATCH`.
  - **Info display**: port mappings show the same type badge as the Ports panel (`internal` for `localhost`, `external`); domain mappings show the full host — `*.` prefix for wildcard mappings, the bare base domain without a leading dot, plus the path — and a `wildcard` badge.
  - **Accessibility / phones**: the dialog is named by its `<h2>` (`useDialogLabel()`); Display name, Environment and Init Script (→ the preset select) have `<label for>`; Repositories and Volume Mounts are `role="group"` lists named by their label; the init textarea is named "Init script content" with autocorrect / autocapitalize / spellcheck off. The pending banner and the save row wrap (the rebuild hint takes its own line on phones), and below 640px the modal is a full-screen sheet with a sticky save row (see **Mobile & Touch Layout**). Banner text: "Settings changes are saved but not yet applied. Rebuild the worker to apply them."
- **Port/Domain mapping panels**: each row resolves the worker's `displayName` from the live container list by `containerName` (fallback `shortName(m.workerId)`), so rows show the friendly label rather than the raw UUID.

## Repository Picker (RepoInput)

`RepoInput.vue` is one repo row (provider select + repo + branch) used by both the Create Worker and the Worker Settings modals. It is provider-agnostic and self-contained: when the caller has a token for the selected provider (`GitProviderInfo.tokenConfigured` from `useGitProviders`), the URL field becomes a searchable dropdown of the provider's repositories (`fullName` — `owner/repo` on GitHub, `group/subgroup/project` on GitLab) with **Create … public/private** entries for the typed path (a bare name goes to the user's own namespace, `a/b/name` to the namespace `a/b`), and the branch field becomes a picker (placeholder `<default> (default)`) loaded after a repo is picked or created — or on open when the row already has a repo. Without a token both are plain inputs. Repo lists come from the module-level `useGitRepos` store (one list per provider, shared by every row; refetched when older than 60s, invalidated when the Create Worker modal opens or the user saves env vars); branch state and create errors are local to the row. Provider/repo/branch controls carry the aria-labels `Git provider`, `Repository` / `Repository URL` and `Branch`; the row's remove button is `Remove repository`. Both modals key rows by a stable per-row key (not the index) so a row keeps its state when an earlier row is removed, and a row never emits after it was removed. On phones the row wraps: provider, branch and remove stay on the first line and the repository field takes a full-width line of its own (`order-last basis-full`, back inline from 640px). `MountInput` rows wrap the same way instead of collapsing (inputs `Host path` / `Container path`, remove `Remove mount`; the `ro` label toggles its own row's checkbox). Repo, branch and path inputs turn off autocapitalize / autocorrect / spellcheck.

The Account modal's **Predefined environment variables** are `PREDEFINED_ENV_VAR_KEYS` plus every provider's `tokenEnvVar` (so a configured self-managed GitLab adds a `GITLAB_<NAME>_TOKEN` input, hinted `GitLab (<name>) token`); providers are loaded before the stored env vars are split into predefined slots and custom rows.

## Resource Metrics & Worker Export/Import UI

**Per-worker metrics** (`useWorkerMetrics`): the only resource metrics — there is no host/system card (host metrics are OS-dependent; everything here goes through the Docker API). Polled by one module-level shared poller (10s `GET /api/worker-metrics`, see **Polling**), read in `AppSidebar` and passed to each `ContainerCard` as a `metric` prop via `metricFor(id)` — so adding cards does not multiply pollers. The card renders a compact `data-testid="worker-metrics"` row (CPU% of host, RAM **used bytes**, Disk **used bytes**, ↓down/↑up) only while running. cpu/mem/net come from `container.stats` (3s server cadence). Disk is sampled server-side on a slower 60s cadence — the container's writable-layer size (`SizeRw`, excludes the base image) plus a `du` of its `/workspace` + agent-data volumes (storage-mode-agnostic; DinD excluded). `formatBytes`/`formatRate` (`app/utils/format.ts`) format the values.

**Worker export**: the card's Export button (`i-lucide-package`, tooltip "Export worker"/"Preparing export…") lives in the workspace group next to Download Workspace. It `fetch`es `GET /api/containers/:id/export` (default-on `docker export` rootfs) with a local `exporting` ref driving a spinner + disabled state — because the server materialises the whole bundle before the response starts, a bare anchor would look like nothing is happening. On completion it saves the response via a blob URL (filename from `Content-Disposition`).

**Worker import** (`ImportWorkerModal.vue`): opened from the sidebar "Import worker" button (`aria-label="Import worker"`). A native file picker (labelled "Export bundle") + optional display-name input (labelled "Display name"); the Import button is disabled until a bundle is chosen. On submit, `useContainers().importContainer(file, displayName)` POSTs the file as the raw `application/x-tar` body to `/api/containers/import`; on success `index.vue`'s `onWorkerImported` refreshes the list and opens a terminal tab for the restored worker.

## OAuth Consent & MCP Access

- **Consent page** (`pages/oauth/consent.vue`, route `/oauth/consent`, no layout): the OAuth authorize endpoint redirects here with a signed query (`client_id`, `scope`, …, `sig`). It loads the client's public info (`/api/auth/oauth2/public-client`), shows the client name, the origin of its `redirect_uri` (where approval sends the user — the tell for a look-alike client name), each requested scope with a user-facing description (`agentor` = full control of the account), and the signed-in email. **Approve** / **Deny** POST `/api/auth/oauth2/consent` (the `oauthProviderClient` plugin attaches the signed query) and follow the returned `{ redirect, url }` back to the client. Direct visits without a signed query show an error and disabled buttons. The global route guard still requires a session, but better-auth only redirects signed-in users here.
- **Login continuation** (`pages/login.vue`): when the URL carries a signed OAuth query (`isOAuthAuthorizationPage()`), the page shows a "Sign in to authorize an application" notice, does not auto-redirect an already signed-in user (the authorization demanded a fresh login), and after email/password or passkey sign-in follows better-auth's `{ redirect, url }` (`followOAuthRedirect()`) to the consent page instead of the dashboard. The global route guard (`middleware/auth.global.ts`) sends a signed-out visitor of `/oauth/consent` to `/login` with the query preserved, so an expired session also resumes the authorization.
- **Account modal → MCP access** (`components/McpAccessSection.vue`, last section of the Account modal, hidden when MCP is disabled): the MCP server URL (from `mcpUrl` in `/api/setup/status`, `select-all`) with a copy button and a `claude mcp add` example, plus the user's authorized applications (`GET /api/account/oauth-apps`) with a two-step **Revoke** (`DELETE /api/account/oauth-apps/:clientId`). Copy uses `copyText()` (works on plain-http LAN origins too): a check icon for 1.5s, or the toast "Copy failed — select the URL and copy it manually".
- **Users modal** (`components/UsersModal.vue`) uses the `/api/users` REST API (the same routes as the MCP user tools) instead of better-auth's session-only admin endpoints.

## Branding

The Agentor mark (robot + containers) is used in two forms:

- **In-app mark** — `app/assets/img/agentor-symbol.png` (transparent, theme-neutral), rendered by `AppLogo.vue`: a single `<img>` (`data-testid="agentor-logo"`, `alt=""` by default because every placement sits next to an "Agentor" heading; pass `alt` when it stands alone) sized by the caller's classes. Placements: the sidebar header (beside the "Agentor" heading + "Orchestrator" subtitle, `h-9`) and above the heading on the login, setup and OAuth consent pages (`h-16`). The text headings are kept — they carry the name for assistive tech and are what the tests anchor on (`h1:has-text("Agentor")`). The image goes through Vite (`~/assets/…`), so it is hashed and cached like any other bundled asset.
- **Favicon & app icon set** — `orchestrator/public/` holds `favicon.ico` (16–256 px embedded), `favicon-16x16/32x32/48x48.png`, `apple-touch-icon.png` (180 px), `android-chrome-192x192/512x512.png` (`purpose: any`), `maskable-icon-192x192/512x512.png` (`purpose: maskable`) and `site.webmanifest` (name `Agentor`, `#030712` theme/background, `start_url` / `scope` / `id` `/`; details in **Progressive Web App**). Nuxt serves `public/` at the site root, and `nuxt.config.ts` → `app.head.link` emits the `icon` / `apple-touch-icon` / `manifest` links on every page. The `theme-color` meta is a single reactive tag set in `app.vue` that follows the colour mode (`#f9fafb` light, `#030712` dark) — there is deliberately no static one in `nuxt.config.ts`.

The README logos (wordmark + tagline) live in `docs/assets/` and are not part of the app bundle: `agentor-logo-light.png` (dark lettering, transparent) for GitHub's light theme and `agentor-logo-dark.png` for dark, selected with a `<picture>` + `prefers-color-scheme` source. The dark file is the original navy-background export with the background keyed out (ImageMagick colour-distance mask), so it sits on GitHub's dark theme without a visible box — it is **not** meant for light backgrounds.

## Theme System

**Architecture:**

## VS Code Editor (code-server)

Browser-based VS Code editor integrated into each worker container via [code-server](https://github.com/coder/code-server). Runs on port 8443 with no authentication (`--auth none`), accessible through the orchestrator's HTTP/WebSocket proxy.

**Architecture:**
- `ServicePane.vue`: unified iframe-based pane for both desktop (noVNC) and editor (code-server), parameterized by endpoint, label, icon, and URL. Starting state: large icon + spinner + "<Label> is starting..." on the terminal background. Running state: a 30px header in the terminal bar colours (green status "<Label> running" with a pulse that honours reduced motion, and an **Open in tab** ghost button with an external-link icon — hidden in an iOS home-screen app, where the new tab would open signed out) over the iframe, which is titled "<Label> for this worker" and allows `clipboard-read; clipboard-write; fullscreen`
- `useContainerServiceStatus.ts`: polls service status endpoint for a container (5s, paused while the pane tab is hidden). It keeps the last status on request errors and only reports `running: false` after 3 consecutive failures (or when the server says so), so a phone waking up does not tear down and reload the noVNC / code-server iframe
- `editor/[containerId]/index.ts`: Combined HTTP+WS handler for bare editor path (h3 `defineEventHandler({ handler, websocket })`)
- `editor/[containerId]/[...path].ts`: Combined HTTP+WS handler for sub-paths (same pattern, strips `/editor/{id}` prefix for WS relay)
- Worker entrypoint starts code-server in Phase 3b (after display stack, before git auth)
- Default workspace folder: `/workspace`

## UI State Persistence

All client-side UI state is consolidated into a single localStorage key (`agentor-ui-state`) managed by the `useUiState` composable (`orchestrator/app/composables/useUiState.ts`). Color mode is the only exception — it stays with `@nuxtjs/color-mode`.

**State shape** (`UiState`, version 1):
- `sidebar.width` — sidebar pixel width (200-700, default 320)
- `sidebar.collapsed` — sidebar collapsed toggle (default false)
- `sidebar.panels` — per-section collapse states: `archived` (default true), `portMappings`, `domainMappings`, `usage`, `images` (default false)
- `panes.rootNode` — serialized `PaneNode` tree (split pane layout + open tabs)
- `panes.focusedNodeId` — which leaf pane group is focused
- `tmux.activeWindows` — `Record<containerId, windowIndex>` for restoring active tmux tab per terminal
- `terminal.fontSize` — terminal font size in px (`null` = device default), `terminal.toolbar` — touch key toolbar mode (`auto` | `show` | `hide`)

**Architecture:**
- Module-level singleton ref, loaded from localStorage on first access
- 500ms debounced writes via `scheduleWrite()`, flushed on `pagehide` and when the page becomes hidden (`visibilitychange`) — iOS Safari and backgrounded / killed PWAs never fire `beforeunload`
- Defensively merges stored JSON into defaults (handles partial/corrupt data)
- `useSidebarResize` reads initial width/collapsed from `useUiState().state` and writes back via `setSidebarWidth()`/`setSidebarCollapsed()`
- `AppSidebar.vue` panel collapse refs are computed get/set backed by `useUiState().state.sidebar.panels`
- `useSplitPanes` initializes `rootNode`/`focusedNodeId` from stored state, rehydrates `_nextNodeId` from the restored tree, and deep-watches for changes
- `useTmuxTabs` uses `getTmuxActiveWindow()`/`setTmuxActiveWindow()` instead of a module-level Map. It pre-selects the saved window before its first fetch (falling back to the first window when the saved one is gone), so reopening a terminal tab restores the last active tmux window; polls persist the active window only when it changed, explicit create / close / activate always persist
- `_resetUiState()` export for testing (clears singleton + timers)

## Log Pane

Centralized log viewer opened via the "Logs" button in the System tab's Quick Links. Each click opens a new independent Logs tab (type `logs`) — multiple log panes can coexist and be arranged side-by-side. All instances share the same underlying module-level log state (one WebSocket, one in-memory entry buffer), so the panes stay in lock-step but each has its own viewport, scroll position, and tab identity.

**Architecture** (`LogPane.vue` + `useLogs` composable):
- `useLogs()` manages module-level singleton state: log entries (a `shallowRef` array), filter state, WebSocket connection, lazy-load state (`loadingMore`, `loadingInitial`, `hasMoreOlder`, `liveTick`). Multiple `LogPane.vue` instances subscribe to this shared state. Every ingested entry is stamped once with a stable key `_k` (monotonic counter) and a preformatted `_t` timestamp (`HH:MM:SS.mmm`, one shared `Intl.DateTimeFormat`); rows render with `:key="entry._k"` + `v-memo`.
- The filter watcher, the page-visibility watcher and `filteredEntries` live in one detached `effectScope`, so all Logs tabs share one filtered list (returned as-is when no filter is active) and one history fetch per filter change.
- **Socket lifecycle**: a subscriber count (mount / unmount of Logs panes) drives the `/ws/logs` connection — the first pane fetches history and connects, the last one closes the socket (entries are kept). After the page has been hidden for 60s the socket closes too; when the page is shown again with a Logs pane open it refetches history and reconnects. Auto-reconnect after 3s on an unexpected disconnect.
- **Live ingest**: WebSocket entries are buffered and appended once per animation frame as a new array (one render and one `liveTick` bump per frame, however fast lines arrive).
- On first mount, fetches 500 most recent entries via `GET /api/logs`, then switches to WebSocket for live updates
- **Lazy load**: scrolling within ~80px of the top calls `loadMore()`, which fetches the next older page via `GET /api/logs?until=<oldest>&limit=500` and prepends the result. Scroll position is anchored to the same content via a `scrollHeight` delta so the user does not jump. A spinner ("Loading older entries…") shows during fetch; a "Beginning of logs" marker shows once no more pages are available.
- **Auto-scroll**: a `liveTick` ref bumped only when the WebSocket pushes a new entry triggers scroll-to-bottom (so pagination prepends never trigger an unwanted jump). On first paint, the pane snaps to the bottom once entries arrive.
- **Soft cap (50,000 entries)** with conditional eviction: only culls from the front when the user is at the bottom (`autoScroll === true`), so scrolled-back history is never yanked out from under the user. Evicted entries are still on disk and can be re-fetched via scroll-up.
- Filters propagate to both the server (paginated fetches use them) and the client (live entries are gated client-side). Changing a filter refetches the most recent page from scratch via an internal `filterEpoch` that invalidates any in-flight `loadMore`.
- Filter bar: source toggles (orchestrator, worker, traefik), level toggles (debug, info, warn, error), text search (300ms debounce). Filter buttons and the auto-scroll button expose `aria-pressed` (filters: the explicit selection — visually every button looks active while none is selected); icon buttons are named "Auto-scroll to bottom" / "Clear all logs"; the search field is "Search logs" (no autocorrect / autocapitalize / spellcheck); `.log-status-text` (Connected / Disconnected) is `role="status"` (the entry count deliberately is not, it changes on every line)
- Color-coded badges: level (debug=gray, info=blue, warn=amber, error=red), source (orchestrator=purple, worker=green, traefik=orange) — from `--log-*` variables defined for light (`.log-pane`) and dark (`.dark .log-pane`) themes; warn rows use `--log-*` amber, error rows `--terminal-danger`; timestamp, empty state and pagination indicator use `--terminal-text-muted`
- **Wrapping**: messages wrap (`.log-message`: `white-space: pre-wrap`, `overflow-wrap: anywhere`) instead of being cut off; badges, timestamp and source id stay on one line, aligned on the first line's baseline. The pane is an inline-size container: at 640px or narrower each row wraps with the message on its own line, the source id is capped at 40% and the search field takes a full line. Coarse pointers get ≥32px filter buttons. The scroll area contains overscroll and sets a Firefox scrollbar colour
- Uses terminal CSS variables (`--terminal-*`) for seamless theme integration

## Polling

Every client-side poller goes through `composables/usePolling.ts`:

- `createPoller(fn, intervalMs, enabled, { immediate? })` — self-rescheduling `setTimeout` loop (`start` / `stop` / `trigger` / `dispose`). Runs never overlap; `trigger()` during a run queues exactly one rerun. It only runs while `enabled()` is true; when that turns true again after a pause, the next run is due one interval after the last one, so data that went stale meanwhile refreshes at once while quick flips cause no bursts. Callback errors are logged with `console.warn`.
- `usePolling(cb, ms, { enabled? })` — component-scoped (starts on mount, disposes on unmount, first run one interval after setup like `setInterval`). Pauses while the page is hidden or offline (`isPageActive()`: `visibilitychange` + `online` / `offline`) **and** while the hosting pane tab is not shown (`PANE_ACTIVE_KEY`, provided by `PaneTabHost`).
- `createSharedPoller(fn, ms)` → `{ use, trigger }` — one module-level poll for data many components read: it runs while at least one subscriber (`use()` during setup) is mounted and the page is active, fetching at once for the first subscriber. Used for the worker list (`useContainers`, 10s; `refresh()` applies only the newest response), port mappings and domain mappings (10s), worker metrics (10s) and usage (5 min). Mutations call `trigger()` instead of waiting for the next tick.
- `utils/assign-if-changed.ts` — `assignIfChanged(ref, next)` assigns only when the JSON differs, so an unchanged poll result does not re-render its readers. A failed port / domain mapping or usage poll keeps the last data.
- Pane-scoped polls pause while their tab is hidden behind another tab of the group and refresh at once when it is shown again (if stale): Apps instances (5s), Desktop / Editor service status (5s), tmux windows (`useTmuxTabs`, 3s, `createPoller` enabled by `paneActive && isPageActive()`; `windows` is only reassigned when the `index:name:active` signature changes). Hidden terminal tabs keep their WebSockets.
- `useDomainMappings().status` is fetched once on first use (retried on the next use after a failure); `/api/app-types` once per page load. The usage panel's "Nm ago" clock (30s) uses `usePolling`, so it pauses while the page is hidden.

## Progressive Web App

The dashboard is an installable PWA, built from plain files in `orchestrator/public/` plus a client plugin — no PWA module.

**Manifest** (`public/site.webmanifest`): `id` / `scope` / `start_url` `/`, `display: standalone`, `orientation: any`, `background_color` / `theme_color` `#030712` (gray-950, the dark page background), `lang: en`, `categories`, `launch_handler.client_mode: ["focus-existing", "auto"]`, and two icon sets — `purpose: any` (`android-chrome-192x192/512x512.png`) and `purpose: maskable` (`maskable-icon-192x192/512x512.png`). The maskable icons put the artwork inside the 40% safe circle on a `#0b111e` fill (the tile colour, so Android adaptive icons show no white frame). Regenerate them from `orchestrator/` with ImageMagick:

```bash
magick public/android-chrome-512x512.png -background '#0b111e' -flatten -resize 72% -gravity center -extent 512x512 -alpha off -depth 8 -strip public/maskable-icon-512x512.png
magick public/maskable-icon-512x512.png -resize 192x192 -alpha off -depth 8 -strip public/maskable-icon-192x192.png
```

**Head** (`nuxt.config.ts` → `app.head`): `<html lang="en">`; viewport `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content` (`viewport-fit=cover` enables the safe-area padding, `resizes-content` makes Android shrink the layout for the soft keyboard; pinch-zoom is never disabled); `application-name`, `mobile-web-app-capable`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-title` (`Agentor`), `apple-mobile-web-app-status-bar-style` (`default`), `format-detection: telephone=no`. The manifest link has `crossorigin="use-credentials"`, so it still loads (and the app stays installable) behind the dashboard's Traefik basic auth. `theme-color` is the single reactive meta in `app.vue` (see **Branding**). `routeRules` serve `/sw.js`, `/offline.html` and `/site.webmanifest` with `cache-control: no-cache`.

**Service worker** (`public/sw.js`) — an offline / server-unreachable fallback for page navigations, nothing else:
- Handles only top-level same-origin `GET` document navigations, network-first: a network error or a `502` / `503` / `504` (what Traefik answers while the orchestrator restarts) gets the cached `offline.html`, everything else the network response.
- Never answers anything under the `BYPASS` prefixes: `/api/`, `/_nuxt/`, `/_nuxt_icon`, `/ws/`, `/editor/`, `/desktop/`, `/mcp`, `/.well-known/`. On Chromium they are also registered as static routes (`event.addRoutes`, source `network`, called from the install handler), so the editor / desktop iframes' subresource requests never even start the worker. **Every new server path prefix that is navigated to directly (proxies, OAuth, downloads) belongs in `BYPASS`.**
- Caches only `offline.html` (cache `agentor-offline-v1`) — no app HTML or assets (Nitro serves `/_nuxt/` immutable). `skipWaiting()` + `clients.claim()`; `activate` deletes older `agentor-*` caches. **Bump `CACHE` whenever `offline.html` changes.** Kill switch: ship a `sw.js` whose install / activate handler calls `self.registration.unregister()` — browsers re-check the file on every navigation.

**Unreachable ≠ signed out** (`middleware/auth.global.ts`): when the session check fails without an HTTP answer (network error) or with a 5xx, the route guard does not send the user to `/login`; with the service worker controlling the page it opens `/offline.html` (which returns to the dashboard once the server answers). A real 401 / no session still goes to `/login`, and without a worker (dev, plain-http LAN) the behaviour is unchanged.

**Offline page** (`public/offline.html`): self-contained (inline CSS / JS, the mark as a `data:` URI — nothing may load from the unreachable server), follows the colour mode from `localStorage['nuxt-color-mode']` (default dark, OS scheme for `system`), safe-area padded. It shows "Agentor is unreachable", "You are offline, or the server is restarting. This page reconnects automatically.", a **Retry** button and an `aria-live` status ("Checking again in N s."). It polls `/api/health` every 5s and also reconnects on the `online` event, then reloads (or goes to `/` when opened directly as `/offline.html`; **Retry** does the same). Reloads within 60s of each other count as consecutive (`sessionStorage['agentor-offline-reloads']`); after 3 the interval backs off to 30s.

**Registration** (`app/plugins/pwa.client.ts`): calls `initPwa()` first, then registers `/sw.js` (scope `/`, `updateViaCache: 'none'`) after `window` load — only in production builds and secure contexts (HTTPS or localhost). The outcome is exposed as `<html data-pwa-sw="unsupported|dev|insecure|registered|failed">`. The dev server unregisters our root-scope worker (a leftover from a production build would keep answering navigations) and leaves code-server's own worker under `/editor/<id>/` alone. Plain-http LAN addresses get neither a worker nor installation; the dashboard works as before.

**Install UX** (`composables/usePwa.ts` + `components/PwaInstallButton.vue`, in the sidebar footer between Account settings and Sign out): `initPwa()` (module-level, idempotent) captures `beforeinstallprompt` (with `preventDefault`, so no mini-infobar), clears it on `appinstalled` and sets the `launchQueue` consumer. `usePwa()` returns `canInstall` (a prompt is available and the app is not standalone) → an icon-only **Install app** button (`i-lucide-monitor-down`) that opens the browser's prompt once and then disappears; and `showIosHint` (iPhone / iPad / iPadOS, not standalone, not dismissed — iOS has no install prompt) → an **Add to Home Screen** share button whose popover says "Tap Share, then Add to Home Screen." with **Dismiss** (persisted in `localStorage['agentor-ios-install-hint-dismissed']`). Nothing renders once the app runs installed (`useDevice().isStandalone`).

**Launches**: with `launch_handler: focus-existing` an app launch is routed into the open window. The consumer ignores plain `/` launches and the document's own load (also after the route guard redirected it), and navigates the window to a deep link — e.g. an MCP OAuth authorize URL opened from another app.

**After an orchestrator self-update** `useUpdates.pollHealth()` keeps the "Reconnecting..." overlay up until the replacement answers — a healthy probe only counts after an observed outage or after ~30s (15 probes; the swap must have happened between two probes) — and then reloads the page, so every client (incl. an installed app without a reload button) runs the new build.

**Launch screen** (`app/spa-loading-template.html`): a fixed full-viewport `#030712` screen (`#f9fafb` under `html.light`) with the 192px app icon bridges the installed app's splash screen and the first render; Nuxt removes it after mount.

**Icons are served locally** (`nuxt.config.ts` → `icon`): `@nuxt/icon` with `provider: 'server'`, `localApiEndpoint: '/_nuxt_icon'` (outside `/api/`, which the auth middleware would 401 on the login page), the `lucide` collection (`@iconify-json/lucide`) in the server bundle, and an explicit `clientBundle.icons` list (Nuxt UI internals + always-visible chrome, 45 icons) that renders without any request. The browser never calls `api.iconify.design`. Use `i-lucide-*` for new icons and add one to `clientBundle.icons` when it is visible on first paint. `clientBundle.scan` stays off: its regex treats Tailwind classes such as `ps-4` as icon collections, and a collection that is not installed fails the production build.

**iOS home-screen apps** keep their own cookie jar (sign in again inside the app) and open new tabs in Safari, where the user is signed out — so `ServicePane` hides **Open in tab** when `navigator.standalone` is true.

## Mobile & Touch Layout

Phones, tablets and short landscape screens get the same dashboard; the terminal-specific parts are in **Terminal Input, Selection & Touch**.

- **Shell**: the `index.vue` root is `.app-shell isolate` — fixed, sized to the visual viewport (`--app-height` / `--app-offset-top` from `plugins/viewport.client.ts`), safe-area padded. `isolate` makes it a stacking context, so the overlay, backdrop and expand button stay below the body-level portals of modals, menus, tooltips and toasts (a modal opened from the phone overlay is painted on top of it).
- **Mobile mode** (`useSidebarResize`: `matchMedia('(max-width: 767px), (pointer: coarse) and (max-height: 500px)')`, evaluated during setup so phones never paint the inline sidebar): the sidebar starts collapsed (transient, never persisted) and opens as an overlay `min(320px, 100vw − 56px)` wide (+ the left inset), sized to the visual viewport (it follows the soft keyboard), safe-area padded, with a shadow, contained overscroll and a strip of tappable backdrop. It closes on a backdrop tap, on Escape (unless a dialog is open — the dialog closes first) and whenever a pane opens (`closeSidebarOnMobile()` in `handleOpenTab` / `handleOpenLogs`, so also after create, import and rebuild). While it is open `<main>` is `inert`. Only the opening slide animates. Landscape phones (`max-height: 500px`) get a compact sidebar header (no subtitle, smaller mark).
- **Focus & inertness**: a collapsed sidebar is `inert`. Collapsing focuses the expand button, expanding focuses the **Collapse sidebar** button (not the first sidebar button — the theme buttons sit in tooltips, which open on programmatic focus). When the overlay closes because a pane opened, focus moves to the expand button only if it was lost or still inside the overlay. A **Skip to panes** link (visible on keyboard focus) jumps to `<main id="main-content">`.
- **Expand button** (`.sidebar-expand-fab`, `title="Expand sidebar"`, `aria-expanded="false"`, 32px) sits at the top-left inside the first pane tab bar. While the sidebar is collapsed `<main>` sets `--pane-leading-inset: 40px`, and the top-left leaf's `PaneGroupTabBar` pads its left edge by it, so the button never covers a tab.
- **Sidebar handle** (desktop layout only): a focusable `role="separator"` (`aria-label="Resize sidebar"`, `aria-valuenow` / `aria-valuemin`); ArrowLeft / ArrowRight resize by 16px and persist. Dragging uses Pointer Events with pointer capture (mouse, touch, pen; primary button only), is delta-based and rAF-coalesced, and keeps the 120px collapse threshold; `touch-action: none` and a ±12px hit area on coarse pointers. Pane separators work the same way (see **Split Pane Layout**).
- **Phone modal sheets** (CSS contract in `main.css`): add `modal-sheet` to the UModal `content` slot, `modal-sheet-body` to its scrolling body and `modal-sheet-footer` to its action row. Below 640px the dialog fills the visual viewport (it follows the soft keyboard) and the footer is sticky with safe-area padding; wider screens keep the centred dialog. Every dashboard modal follows it (see **Modals & Forms**).
- **Touch polish** (global rules in `main.css`): larger targets on coarse pointers (`pointer-coarse:` variants; sidebar tabs, More button, dropdown items, system links, card and footer buttons); `touch-action: manipulation` and no tap highlight on buttons, links, labels, selects and tabs; no iOS long-press callout or text selection on tabs; on iOS touch devices `input` / `select` / `textarea` are forced to 16px so focusing them does not zoom the page; inset keyboard focus rings on sidebar tabs, More, dropdown items, system links, the expand button and pane tabs; `prefers-reduced-motion` turns off the sidebar slide. Empty states and System card headers use higher-contrast grays.
- **Auth pages** (login, setup, OAuth consent): one `<main>` landmark each with `min-h-dvh` and safe-area padding; errors are `role="alert"`; setup's Password / Passkey toggles expose `aria-pressed`; the email fields turn off autocapitalize / autocorrect / spellcheck.
- **Empty pane area** (`TerminalPlaceholder`): on the terminal background, "Create a worker from the sidebar to get started" plus a **Create worker** button that sets the shared `useState('create-worker-modal-open')` — the state `index.vue` uses for the New Worker modal.

## Modals & Forms

- **Dialog names**: Nuxt UI's `UModal` only renders a `DialogTitle` for its `title` prop, so a modal that draws its own heading would point `aria-labelledby` at a missing element. `useDialogLabel()` returns `{ titleId, content }`; use `<UModal :content="content">` + `<h2 :id="titleId">`. Every dashboard modal is named by its heading (New Worker, Account settings, Environments, Capabilities, Instructions, Init Scripts, System Settings, Users, Import Worker, Upload to Workspace, `<name> — Settings`), so tests find them with `getByRole('dialog', { name })`. Close / Cancel buttons call a named `close()`.
- **Sheets**: all of them use the `modal-sheet*` contract (full-screen on phones, sticky action rows: New Worker Create / Cancel, Import / Cancel, Upload / Cancel, the environment and list editors' Create / Update / Cancel / Close, System Settings Close, the Worker Settings save row).
- **New Worker**: Repositories and Volume Mounts are `role="group"` lists named by their label (so each mount row's `ro` label toggles its own checkbox instead of focusing the first Host path); the init textarea sits next to (not inside) the Init Script field and is named "Init script content".
- **Account settings**: predefined env var eye toggles are named `Show <KEY>`, the custom row's `Show value`, both with `aria-pressed`; custom rows remove with `Remove variable` and stack on phones (KEY full width, value + buttons below). Success messages are `role="status"`, errors `role="alert"`. Env var and SSH key inputs turn off autocapitalize / autocorrect / spellcheck.
- **System Settings** (`SettingsModal.vue`): `/api/settings` is fetched each time the modal opens — not at dashboard load (where non-admins got a 403) and not on close. A failed load shows an error (`role="alert"`) instead of an empty list; section headers expose `aria-expanded`; on phones each setting stacks its label above its value.
- **Users**: on phones a row's actions (Make admin / Demote, Reset password, Delete) wrap onto their own right-aligned line; errors are `role="alert"`.
- **Environment editor**: lucide icons, bolder section legends, higher-contrast help text, `aria-expanded` on the domain-list expanders, a keyboard focus ring on the network mode cards, Resource Limits stacked on phones, `inputmode="decimal"` on CPU.
- **Upload** (`UploadModal.vue` + `FileDropZone.vue`): the drop zone (`role="button"`, `aria-label="Choose files to upload"`, Enter / Space, focus ring) opens a plain multi-file picker, so phones can pick files ("or click to choose files", on touch devices "Tap to choose files"); a separate **Choose a folder** button below it opens the folder picker where the browser supports `webkitdirectory`. Dropping files or folders works as before. Per-file remove buttons are named `Remove <name>` and stay visible on focus and on touch screens; errors are `role="alert"`.
